How it works

Secure Vault explained.

Learn how your data is protected, how authentication is handled, and what makes this vault a strong choice for private note keeping.

Authentication

Login sessions are stored server-side using Flask sessions. Your user identity is verified on every protected request, and the vault ensures only authenticated users can access their notes.

Encryption

Notes are encrypted before they reach the database using AES-GCM. This means titles and contents are stored as ciphertext, and only the app can decrypt them with the encryption key.

Secure storage

Encrypted note data is saved to the database, while the raw plaintext never persists. The database only sees ciphertext and nonces, so your secrets remain confidential.

Data integrity

AES-GCM provides both confidentiality and integrity. This prevents tampering and ensures that decrypted notes are exactly the same as when they were encrypted.

Rate limiting

Login, registration, and note actions are protected by request rate limits. This reduces abuse and makes brute-force attacks much harder.

Best practices

Passwords are hashed with bcrypt, secrets are kept out of source control using environment variables, and sensitive routes are only accessible after login.
